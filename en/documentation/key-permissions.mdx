A permission (scope) is a string in the API key's rule list. Every endpoint checks its own permission: a key without it gets `403`. Create and configure keys in the [dashboard](https://erlcrussia.com/my/tokens) after signing in with Discord — permissions are selected there too.

## Getting permissions

1. Sign in with Discord and open [My tokens](https://erlcrussia.com/my/tokens).
2. Create a key and tick the permissions you need — the names match the table below.
3. Some permissions are enabled only when explicitly selected (for example, `ads.write` and `action:*` actions).

Send the key in the `erlcrussia-api-key` header or as `Authorization: Bearer <API key>`.

## Permission kinds

| Kind | Form | Purpose |
|---|---|---|
| Endpoint | `module.read`, `module.write` | Access to read or write endpoints. |
| Query | `query:Name` | The `query` parameter in ER:LC responses (which data to return). |
| Action | `action:name` | A specific operation in CivOps modules. |
| Guild action | `action:guild:<id>` | CivOps operations limited to one Discord guild. |

<Note>
An empty permission list does not restrict the key: without explicit rules the key's mode (`full` or `restricted`) applies. Each endpoint page states the required permission, e.g. "requires `ads.read`".
</Note>
