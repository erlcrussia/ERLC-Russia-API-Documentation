Rate limits in the ER:LC Russia API are **custom and dynamic**: they are configured via the policy engine, can vary depending on IP address and API key tier, and automatically scale with active subscription benefits.

The table below lists **baseline default values**. The actual limits enforced for your application are defined exclusively by server response headers. Clients and bots should avoid hardcoding static limits and should instead inspect the `X-RateLimit-*` headers dynamically.

## Standard routes

| Group | Baseline limit |
|---|---|
| `/v3/cdn/*`, `/v3/user-assets/*`, `/v3/users`, `/v3/keys`, `/v3/points/*`, `/v3/health` | 20 requests per minute |
| `/v3/erlc/*`, `/v3/civops/*`, `/v3/subscriptions/*`, `/v3/ads/*` | 120 requests per minute |
| `/v3/stats` without an API key | 40 requests per minute |
| `/v3/stats` with an API key | 120 requests per minute |
| `/v3/ai/*` | 120 requests per second |

Standard routes share a counter per key across methods and routes; requests without credentials use the IP address. AI has a separate one-second window. Checking a file with GET and uploading it with POST count as separate requests. When rate-limited, pause requests and retry after the period indicated in headers.

## Authorization

OAuth login and callbacks: 10 requests per minute per signed session cookie. Other user auth routes allow 250 requests per session or 60 per anonymous visitor.

Anonymous requests also have a shared IP limit: 120 per minute for login and 240 for other auth routes. The window resets at the start of each calendar minute.

## How to navigate using response headers (HTTP Headers)

Every API response includes rate-limit headers to help client applications track current quota status:

| Header | Description | How client should use it |
|---|---|---|
| `X-RateLimit-Limit` | Request ceiling for the active window | Shows your key's personalized limit based on policies and subscription |
| `X-RateLimit-Remaining` | Remaining requests available | When approaching `0`, the client should slow down request dispatch (client-side throttling) |
| `X-RateLimit-Reset` | Window reset timestamp (Unix ms) | Exact point in time when the `Remaining` quota fully resets |
| `Retry-After` | Required backoff delay in seconds (on `429`) | Mandatory delay before retrying the rejected request |

```json
{
  "code": 5016,
  "message": "Rate Limit Exceeded",
  "retry_after": 30,
  "details": {"limit": 20, "count": 21, "excess": 1, "reset_at": 1792083600000}
}
```

The auth limiter omits details. A spam ban from the standard middleware returns code=5039, message=spam_blocked, blocked_until, and remaining_seconds. Standard windows have a threshold of 400 excess requests and a base ban of five minutes; AI uses a threshold of 200 excess requests per second.

Rate limiting does not make mutations idempotent. After a network interruption, inspect the resource before retrying. An explicit CDN path conflict returns 409; it is neither a 429 response nor confirmation of a successful overwrite.

## Cloudflare protection

Cloudflare may also reject or block requests independently of API limits, including high traffic from a single IP address. There is no universal guaranteed threshold of 10,000 requests per second: behavior depends on security rules and traffic characteristics. [Cloudflare](https://developers.cloudflare.com/waf/rate-limiting-rules/).
