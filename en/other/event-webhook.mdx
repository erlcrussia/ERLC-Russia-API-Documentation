To receive webhooks from the game:

1. You can configure webhooks in two ways:
   - In your personal account on the website: go to **Tokens -> Webhooks** (`/my/tokens?tab=webhooks`).
   - On our Discord server: run the `/webhook manage` command.
2. Specify the URL of your **custom** webhook and select servers:
   - **All servers** (default) — the webhook will receive events from all project servers.
   - **Specific servers** — the webhook will only receive events from the selected game servers.
3. Before saving the URL, make sure to click "Test":
   - The system will send a signed ping request. If your endpoint responds with HTTP `200 OK`, the webhook is verified and ready.
4. After successful verification, activate data reception.

<Danger>
   **We do NOT support direct Discord webhooks. The system works exclusively with custom webhooks (your own handlers/endpoints).**
</Danger>

Your endpoint must verify Ed25519 signatures on every request. The game will only save URLs that pass verification.

---

### Headers & Multi-Server Routing

Every outgoing webhook includes information about the origin server:

#### HTTP Headers:
* `X-Signature-Ed25519` — hex-encoded Ed25519 signature.
* `X-Signature-Timestamp` — Unix timestamp (in seconds).
* `X-Server-ID` — ID of the game server where the event occurred.
* `X-Server-Name` — human-friendly server alias/name (e.g., `MRP 1`, `MVD`), if configured by administrators.

#### Request Body (JSON):
* `server_id` (string) — game server ID.
* `server_name` (string) — server alias/name.
* Event payload (chat commands, emergency call data, etc.).

---

### Requirements

#### Your endpoint must accept

* `POST` requests with a JSON body.
* These headers on every signed request:
  * `X-Signature-Ed25519` (hex-encoded Ed25519 signature).
  * `X-Signature-Timestamp` (Unix timestamp string).
  * `X-Server-ID` (game server ID).
  * `X-Server-Name` (game server name/alias).

#### Your Endpoint Must:

1. Read the **raw bytes of the request body** exactly as received (do not re-serialize JSON).
2. Read `X-Signature-Timestamp`.
3. Read `X-Signature-Ed25519`.
4. Verify the signature for:

   `message = timestamp + raw_body`

   Where `timestamp` is the header value as a string, concatenated directly with the raw body bytes.
5. Return:
   * **2xx** only if the signature is valid.
   * **4xx** if headers are missing, invalid, or signature verification fails.

### Implementation Details

#### Input Data

* `timestamp`: exact string from `X-Signature-Timestamp`.
* `sigHex`: exact string from `X-Signature-Ed25519` (hex).
* `rawBody`: raw bytes of the request body.

#### Steps

1. Decode `sigHex` from hex to bytes.
2. Construct `message` as:
   * `timestamp` bytes in UTF-8
   * Immediately followed by `rawBody`
3. Verify the Ed25519 signature using the public key above.

#### Common Mistakes

* Do not use a parsed JSON object for verification. Use only raw body bytes.
* Do not add separators or spaces between the timestamp and body.
* Treat the signature as hex, not base64.
* Make sure your framework doesn't consume the body before you capture it.

### What events are sent?

Currently, the game sends webhooks for:

* Messages starting with **;**
  * This allows creating custom in-game commands!
* Emergency Calls

New events may be added in the future. Note: the webhook system is not intended to replace HTTP API polling or WebSocket.
