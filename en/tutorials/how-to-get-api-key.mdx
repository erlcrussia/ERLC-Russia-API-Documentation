## Getting access

<Steps>
  <Step title="Sign in on the website">
    Sign in with Discord on the [keys page](https://erlcrussia.com/my/tokens). It shows the permissions and keys issued to your account. Contact project administrators in Discord if access is missing; view commands do not grant new permissions.
  </Step>
  <Step title="Wait for approval">
    Once approved, the permissions are linked to your Discord account.
  </Step>
  <Step title="Open your keys on the website">
    Keys and webhooks are on [erlcrussia.com/my/tokens](https://erlcrussia.com/my/tokens) after you sign in with Discord.
  </Step>
</Steps>

## Key types

| Key | Used for | Where to find it |
|---|---|---|
| API key | HTTP requests to API V3 | `/my/tokens/api`, the `/api view` command |
| WebSocket key | Connecting to the [WebSocket](/en/other/websocket-gateway). The HTTP key does not work there | `/my/tokens/websocket`, the `/websocket view` command |
| AI key (`sk-…`) | The [AI API](/en/openai-api/v1/overview) | `/my/tokens/studio` |

Event webhooks are set up on `/my/tokens/webhooks`; you can also view them with the `/webhook view` command. See [Event webhook](/en/other/event-webhook).

## Sending the key

Send the API key in the `erlcrussia-api-key` header:

```http
erlcrussia-api-key: YOUR_API_KEY
```

`Authorization: Bearer YOUR_API_KEY` is accepted too. Keys in query parameters are not accepted.

<Danger>
  Do not publish keys or keep them in code that runs in the browser. If a key leaks, regenerate it right away with [`POST /v3/keys`](/en/reference/v3/keys/regenerate-keys) and contact the project administrators.
</Danger>
