Las cabeceras de límite se incluyen en rutas limitadas. Las claves maestras y UNLIMITED_API_KEYS omiten este límite y pueden no recibir X-RateLimit-*. Los nombres de cabecera HTTP no distinguen mayúsculas. Una clave válida nueva usa primero el límite por IP; tras calentar la caché de credenciales usa el personal (por ejemplo, 40 → 120 en estadísticas). Retry-After se envía al limitar.

| Cabecera | Significado |
|---|---|
| `X-RateLimit-Limit` | Solicitudes permitidas en la ventana actual |
| `X-RateLimit-Remaining` | Solicitudes restantes |
| `X-RateLimit-Reset` | Cuándo se reinicia la ventana, tiempo Unix en milisegundos |
| `Retry-After` | Segundos de espera antes de reintentar |

En los métodos compatibles con OpenAI `/v1/*` los mismos valores usan los nombres de OpenAI: `x-ratelimit-limit-requests`, `x-ratelimit-remaining-requests` y `x-ratelimit-reset-requests` (tiempo hasta el reinicio, por ejemplo `1s`). Consulta el [resumen de la API de IA](/es/openai-api/v1/overview).

## Respuesta 429

Al superar el límite, la API responde con HTTP 429. El cuerpo solo trae el código y el mensaje; el tiempo de espera va en las cabeceras:

```json
{
  "code": 5016,
  "message": "Rate Limit Exceeded"
}
```

Si sigues enviando solicitudes tras un 429, la clave o la IP se bloquean un tiempo: recibes el código `5039` y `Retry-After` indica cuánto esperar.

## Cómo tratarlo

* Vigila `X-RateLimit-Remaining` y reduce el ritmo cuando se acerque a cero.
* Tras un 429, espera `Retry-After` segundos y reintenta solo la solicitud rechazada.
* No repitas a ciegas solicitudes de escritura tras un fallo de red: comprueba antes si se aplicaron.
* Guarda en caché las respuestas que cambian poco.

<Warning>
  Delante de la API está Cloudflare, con sus propios límites. Si una IP envía demasiadas solicitudes, Cloudflare responde con el error `1015` (HTTP 429): es su propia página, no JSON de la API, y sin cabeceras `X-RateLimit-*`. Reduce el ritmo y espera unos minutos: reintentar durante el bloqueo lo alarga.
</Warning>
