Los límites pueden cambiar y variar según la dirección IP y la clave API. La tabla muestra valores de referencia; las cabeceras de respuesta indican los límites aplicados. Respeta `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset` y `Retry-After`.

## Rutas estándar

| Grupo | Límite |
|---|---|
| `/v3/cdn/*`, `/v3/users`, `/v3/keys`, `/v3/points/*`, `/v3/health` | 20 solicitudes por minuto |
| `/v3/erlc/*`, `/v3/civops/*`, `/v3/subscriptions/*`, `/v3/admin/*` | 120 solicitudes por minuto |
| `/v3/stats` sin clave de API | 40 solicitudes por minuto |
| `/v3/stats` con clave de API | 120 solicitudes por minuto |
| `/v3/ai/*`, `/v1/chat*`, `/v1/models*`, `/v1/audio/*` | 120 solicitudes por segundo |

Las rutas estándar comparten un contador por clave entre métodos y rutas; sin credenciales se usa la IP. AI tiene una ventana independiente de un segundo. Comprobar un archivo mediante GET y subirlo mediante POST cuenta como dos solicitudes. Al alcanzar el límite, detenga el envío y repita únicamente la solicitud rechazada tras la espera indicada.

## Autorización

El inicio de sesión OAuth, sus callbacks y session/init permiten 10 solicitudes por minuto por visitante con cookie firmada o sesión verificada. Las demás rutas de autenticación del usuario permiten 250 por sesión o 60 por visitante anónimo.

Las solicitudes anónimas tienen además un límite compartido por IP: 120 por minuto para iniciar sesión y 240 para las demás rutas de autenticación. El visitante se identifica mediante la cookie HttpOnly firmada erlc_auth_visitor. La ventana se reinicia al comenzar cada minuto. Estas rutas no aplican el bloqueo de cinco minutos del limitador estándar.

## Cabeceras y respuesta 429

| Cabecera | Valor |
|---|---|
| `X-RateLimit-Limit` | Límite de la ventana actual |
| `X-RateLimit-Remaining` | Solicitudes restantes |
| `X-RateLimit-Reset` | Marca de tiempo Unix en milisegundos |
| `Retry-After` | Segundos de espera tras un 429 |

```json
{
  "code": 5016,
  "message": "Rate Limit Exceeded",
  "retry_after": 30,
  "details": {"limit": 20, "count": 21, "excess": 1, "reset_at": 1792083600000}
}
```

El limitador de autenticación omite details. Un bloqueo por spam del middleware estándar devuelve code=5039, message=spam_blocked, blocked_until y remaining_seconds. La ventana estándar tiene un umbral de 400 solicitudes excedentes y un bloqueo base de cinco minutos; AI usa un umbral de 200 solicitudes excedentes por segundo.

El limitador no convierte las modificaciones en operaciones idempotentes. Tras una interrupción de red, compruebe primero el estado del recurso. Un conflicto de ruta explícita en CDN devuelve 409; no es un 429 ni confirma una sobrescritura correcta.

## Protección de Cloudflare

Cloudflare también puede rechazar o bloquear solicitudes independientemente de los límites de la API, incluido un gran volumen desde una sola IP. No existe un umbral universal garantizado de 10.000 solicitudes por segundo: depende de las reglas de seguridad y las características del tráfico. [Cloudflare](https://developers.cloudflare.com/waf/rate-limiting-rules/).
