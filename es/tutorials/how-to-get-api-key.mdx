## Obtener acceso

<Steps>
  <Step title="Inicia sesión en el sitio">
    Inicia sesión con Discord en la [página de claves](https://erlcrussia.com/my/tokens). Muestra los permisos y claves de tu cuenta. Si falta acceso, contacta con la administración del proyecto en Discord; los comandos de consulta no conceden permisos nuevos.
  </Step>
  <Step title="Espera la aprobación">
    Tras la aprobación, los permisos se vinculan a tu cuenta de Discord.
  </Step>
  <Step title="Abre tus claves en el sitio">
    Las claves y los webhooks están en [erlcrussia.com/my/tokens](https://erlcrussia.com/my/tokens) tras iniciar sesión con Discord.
  </Step>
</Steps>

## Tipos de claves

| Clave | Para qué | Dónde verla |
|---|---|---|
| Clave de API | Solicitudes HTTP a la API V3 | `/my/tokens/api`, comando `/api view` |
| Clave de WebSocket | Conectarse al [WebSocket](/es/other/websocket-gateway). La clave HTTP no sirve | `/my/tokens/websocket`, comando `/websocket view` |
| Clave de IA (`sk-…`) | La [AI API](/es/openai-api/v1/overview) | `/my/tokens/studio` |

Los webhooks de eventos se configuran en `/my/tokens/webhooks`; también puedes verlos con el comando `/webhook view`. Consulta [Webhook de eventos](/es/other/event-webhook).

## Cómo enviar la clave

Envía la clave en la cabecera `erlcrussia-api-key`:

```http
erlcrussia-api-key: YOUR_API_KEY
```

También se acepta `Authorization: Bearer YOUR_API_KEY`. No se aceptan claves en parámetros de consulta.

<Danger>
  No publiques las claves ni las guardes en código que se ejecuta en el navegador. Si una clave se filtra, regénerala con [`POST /v3/keys`](/es/reference/v3/keys/regenerate-keys) y avisa a la administración del proyecto.
</Danger>
