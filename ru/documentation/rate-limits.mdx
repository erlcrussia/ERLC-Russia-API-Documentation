Лимиты запросов в API ER:LC Россия являются **кастомными и динамическими**: они настраиваются через систему политик, могут отличаться для разных IP-адресов, типов API-ключей и автоматически увеличиваться при наличии активных подписок.

В таблице приведены **базовые значения по умолчанию**. Фактические лимиты для вашего приложения определяются исключительно заголовками ответа сервера. Клиентским библиотекам и ботам рекомендуется не фиксировать числовые лимиты в коде, а динамически ориентироваться на заголовки `X-RateLimit-*`.

## Обычные маршруты

| Группа | Базовый лимит |
|---|---|
| `/v3/cdn/*`, `/v3/user-assets/*`, `/v3/users`, `/v3/keys`, `/v3/points/*`, `/v3/health` | 20 запросов в минуту |
| `/v3/erlc/*`, `/v3/civops/*`, `/v3/subscriptions/*`, `/v3/ads/*` | 120 запросов в минуту |
| `/v3/stats` без API-ключа | 40 запросов в минуту |
| `/v3/stats` с API-ключом | 120 запросов в минуту |
| `/v3/ai/*` | 120 запросов в секунду |

Обычный счётчик общий для ключа между методами и маршрутами; при обращении без ключа лимит привязывается к IP-адресу клиента. AI-маршруты имеют отдельное секундное окно. GET-проверка существования файла и POST-загрузка учитываются как отдельные запросы. После исчерпания лимита приостановите отправку и повторите запрос после указанного в заголовках интервала.

## Авторизация

OAuth-вход и callback: 10 запросов в минуту на пользователя с подписанной сессионной cookie. Остальные пользовательские auth-маршруты: 250 на активную сессию либо 60 на анонимного посетителя.

Дополнительный общий IP-потолок для анонимных запросов: 120 в минуту для входа и 240 для остальных auth-маршрутов. Окно сбрасывается на границе календарной минуты.

## Как ориентироваться по заголовкам (HTTP Headers)

При каждом запросе API возвращает набор заголовков, по которым клиент должен определять текущее состояние своей квоты:

| Заголовок | Описание | Как использовать клиенту |
|---|---|---|
| `X-RateLimit-Limit` | Назначенный потолок запросов в текущем окне | Отображает персональный лимит вашего ключа с учётом тарифа и политик |
| `X-RateLimit-Remaining` | Оставшееся количество доступных запросов | Если значение приближается к `0`, клиенту следует замедлить отправку запросов (client-side throttling) |
| `X-RateLimit-Reset` | Время сброса лимита (Unix timestamp в миллисекундах) | Показывает точный момент, когда квота `Remaining` полностью обновится |
| `Retry-After` | Время ожидания в секундах (при статусе `429`) | Обязательная пауза перед повторной отправкой отклонённого запроса |

```json
{
  "code": 5016,
  "message": "Rate Limit Exceeded",
  "retry_after": 30,
  "details": {"limit": 20, "count": 21, "excess": 1, "reset_at": 1792083600000}
}
```

У auth-ограничителя поле details отсутствует. При спам-блокировке общий middleware возвращает code=5039, message=spam_blocked, blocked_until и remaining_seconds. Порог обычного окна — 400 лишних запросов, базовая блокировка — 5 минут; AI использует порог 200 лишних запросов в секунду.

Ограничитель не делает изменяющие запросы идемпотентными. После сетевого обрыва сначала проверьте состояние ресурса. Для CDN явный конфликт пути даёт 409; это не ответ 429 и не подтверждение успешной перезаписи.

## Защита Cloudflare

Cloudflare также может отклонять или блокировать запросы независимо от лимитов API, в том числе при большом потоке с одного IP-адреса. Единого гарантированного порога в 10 000 запросов в секунду нет: поведение зависит от правил защиты и характеристик трафика. [Cloudflare](https://developers.cloudflare.com/waf/rate-limiting-rules/).
