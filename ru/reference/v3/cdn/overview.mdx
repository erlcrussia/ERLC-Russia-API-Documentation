# Архитектура CDN V3

## Как устроено хранение

Каждый ассет хранится в MinIO под ключом **`{domain}/{path}`**:

| Часть ключа | Что это |
|---|---|
| `domain` | Slug организации; `default` — только ER:LC Россия. Либо подтверждённый кастомный домен организации |
| `path` | Произвольный путь файла, например `branding/logo.png` |

Единого «префикса категории» больше нет: если путь задан явно, он используется как есть. Если путь не задан, он генерируется автоматически (по расширению файла).

## Организация и доступ

Перед работой привяжите свой ключ к организации:

```bash
curl -X PUT https://api.erlcrussia.com/v3/cdn/team \
  -H 'erlcrussia-api-key: YOUR_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{"teamId":"YOUR_TEAM_ID"}'
```

Владелец ключа должен быть владельцем, администратором или участником организации с разрешением CDN. Каждый запрос повторно проверяет членство. Без привязки ключа запрос отклоняется. Необязательный `teamId` в query должен совпадать с привязкой. Публичные CDN-маршруты не принимают мастер-ключ или внутренний секрет вместо пользовательского ключа; требуется разрешение V3.

На `cdn.erlcrussia.com` обычная организация получает только `/{slug}/...`. Slug содержит строчные латинские буквы, цифры, `_` и `-`. Корень и `/erlcrussia/...` принадлежат основной организации ER:LC Россия. Она также не может записывать в зарезервированные пути других организаций. На подтверждённом кастомном домене организации доступны произвольные пути внутри её namespace.

Ассеты, папки, статистика и операции по ID ограничены организацией ключа. Папка интерфейса не заменяет проверку владельца ресурса.

## Поток загрузки

```
UI → POST /v3/cdn/assets?path=branding/logo.png
        заголовок: erlcrussia-api-key
API  → объект в MinIO:  {domain}/{path}
API  → запись в базу
API  → асинхронно POST {EDGE}/v3/warm
        заголовок: erlcrussia-api-edge-key
        тело: { domain, path, mimeType, size, sha256, isPinned }
EDGE → GET MinIO напрямую, кладёт файл на SSD
```

URL для скачивания передавать не нужно: edge сам собирает ключ из `domain` и `path`.

## Поток чтения

```
Браузер → GET https://cdn.erlcrussia.com/{domain}/{path}
EDGE:
  HIT  → отдаёт файл с SSD (Range 206, ETag, 304)
  MISS → GET MinIO/{domain}/{path} → отдаёт клиенту и асинхронно кладёт на SSD
```

API V3 в этой цепочке не участвует. Origin-эндпоинтов у API нет, доставка через API V3 не предусмотрена.

## Поток сброса кэша

```
UI → POST /v3/cdn/assets/purge?domain=default&prefix=branding/
API → POST {EDGE}/v3/purge?domain=default&prefix=branding/
        заголовок: erlcrussia-api-edge-key
EDGE → удаляет файлы с SSD и записи из SQLite
Следующий запрос → MISS → edge сам тянет свежий файл из MinIO
```

## Папки и публичные пути

| Действие | Влияние на файлы |
|---|---|
| Создание папки | нет |
| Переименование папки | **нет**, файлы остаются на своих путях |
| Удаление папки | **нет**, файлы остаются и теряют привязку |
| `PATCH /cdn/assets` с `folderId` | только группировка в UI |
| `PATCH /cdn/assets` с `path` | физический перенос объекта в MinIO |

## Авторизация

| Заголовок | Где принимается |
|---|---|
| `erlcrussia-api-key` | все публичные маршруты `/v3/cdn/*` |
| `erlcrussia-api-master-key` | `/v3/admin/cdn/*` для интерфейса |
| `erlcrussia-api-edge-key` | только `/v3/*` Go edge-сервиса, в V3 не используется |

Ключ передаётся исключительно в заголовке. Query-параметры `?apiKey=` и `?token=` не поддерживаются.

## Соглашения по query-параметрам

| Параметр | Значение |
|---|---|
| `domain` | Пространство имён. По умолчанию slug организации ключа (`default` только для ER:LC Россия) |
| `ids` | Список ID через запятую |
| `path` | Точный путь внутри пространства имён |
| `prefix` | Префикс пути для группы файлов |
| `folderId` | Папка интерфейса: `root` — без папки, `all` — без фильтра |
| `page`, `limit` | Пагинация списка, `limit` максимум 100 |

`pathEnabled` управляет префиксом только новых загрузок без явного path. Папки не перемещают уже загруженные файлы. Кастомные домены управляются через `/v3/cdn/custom-domains`; `/v3/cdn/domains` перечисляет namespace с ассетами.
