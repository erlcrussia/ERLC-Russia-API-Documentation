Базовый адрес API: `https://api.erlcrussia.com/v3`.

## Авторизация

Серверная интеграция передаёт пользовательский ключ в `erlcrussia-api-key`. Управление CDN и редиректами требует привязки ключа к организации и разрешения владельца ключа на соответствующий сервис. Секретные ключи не помещаются в браузерный JavaScript. Маршруты профиля и подписок пользователя используют сессию erlc_auth, а входящие PRC-вебхуки — подпись.

## Выбор маршрута

| Задача | Маршрут |
|---|---|
| Статус игрового сервера | `GET /erlc/server` |
| Discord/Roblox связи | `GET /users`, `POST /users` |
| Файлы и папки организации | `/cdn/assets`, `/cdn/folders` |
| Кастомные CDN-домены | `/cdn/custom-domains` |
| Редиректы организации | `/teams/{teamId}/redirects` |
| Ключи владельца | `GET /keys?api=true` |
| Статус сервиса | `GET /health` |

## Форматы ответов

Формат ответа зависит от метода. GET users с одиночным discordId возвращает `{ "robloxId": "123456789" }`; plural-параметры и POST возвращают массив пар. Не найденная одиночная связь даёт 404, пустой batch — 200 и []. ID передавайте строками и сопоставляйте batch по ID, а не по позиции.

GET cdn/assets возвращает assets, pagination и stats. Точный path без ids/prefix возвращает asset. GET cdn/custom-domains возвращает массив без success. GET keys возвращает массив для одного типа и объект api/websocket для двух типов. Поле restrictions не является полной эффективной политикой доступа.

GET keys возвращает секретные значения ключей владельца, включая другие его серверы. Используйте его только в доверенной серверной среде и не логируйте ответ. Привязку ключа к организации не следует считать ограничением для всех остальных ресурсов владельца.

## Ошибки и повторные запросы

Основные поля ошибки — `code` и `message`; дополнительные поля зависят от причины. При HTTP 429 учитывайте `Retry-After` и заголовки лимитов. Значения могут меняться; базовые значения и правила повторных запросов описаны в [ограничениях запросов](/ru/documentation/rate-limits).

Загрузка CDN возвращает 200. Повтор занятого явного path возвращает 409 и не перезаписывает объект. Для релизов используйте новый префикс; не повторяйте изменяющую операцию вслепую после сетевого обрыва. Purge планируется асинхронно: success не подтверждает завершение очистки всех уровней кэша.

GET health может вернуть 200 со status=degraded при проблеме Redis или игрового кэша; недоступная база даёт 503. Проверяйте одновременно HTTP-статус и JSON.

См. [интеграции CDN](/ru/other/cdn-integration) и [Next.js и CDN](/ru/tutorials/nextjs-cdn-integration). Поля JSON, HTTP-заголовки и значения примеров не переводятся, чтобы сохранять контракт.
