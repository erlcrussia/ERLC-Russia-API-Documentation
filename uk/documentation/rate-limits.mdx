Ліміти запитів в API ER:LC Росія є **кастомними та динамічними**: вони налаштовуються через систему політик, можуть відрізнятися для різних IP-адрес і рівнів ключів та автоматично збільшуються за наявності активних підписок.

У таблиці наведено **базові значення за замовчуванням**. Фактичні обмеження для вашого застосунку визначаються виключно заголовками відповіді сервера. Клієнтським бібліотекам і ботам рекомендується не фіксувати числові ліміти в коді, а динамічно орієнтуватися на заголовки `X-RateLimit-*`.

## Звичайні маршрути

| Група | Базовий ліміт |
|---|---|
| `/v3/cdn/*`, `/v3/user-assets/*`, `/v3/users`, `/v3/keys`, `/v3/points/*`, `/v3/health` | 20 запитів за хвилину |
| `/v3/erlc/*`, `/v3/civops/*`, `/v3/subscriptions/*`, `/v3/ads/*` | 120 запитів за хвилину |
| `/v3/stats` без API-ключа | 40 запитів за хвилину |
| `/v3/stats` з API-ключем | 120 запитів за хвилину |
| `/v3/ai/*` | 120 запитів за секунду |

Звичайний лічильник спільний для ключа між методами й маршрутами; без credentials використовується IP. AI має окреме секундне вікно. GET-перевірка файлу та POST-завантаження рахуються окремо. Після вичерпання ліміту призупиніть запити й повторіть відхилений після інтервалу, вказаного в заголовках.

## Авторизація

OAuth-вхід і callback: 10 запитів за хвилину на користувача з підписаною сесійною cookie. Інші користувацькі auth-маршрути: 250 на активну сесію або 60 на анонімного відвідувача.

Додатковий спільний IP-ліміт анонімних запитів: 120 за хвилину для входу та 240 для інших auth-маршрутів. Вікно скидається на початку календарної хвилини.

## Як орієнтуватися за заголовками (HTTP Headers)

При кожному запиті API повертає набір заголовків, за якими клієнт повинен визначати стан своєї квоти:

| Заголовок | Опис | Як використовувати клієнту |
|---|---|---|
| `X-RateLimit-Limit` | Призначений потолок запитів у поточному вікні | Показує персональний ліміт вашого ключа з урахуванням тарифу та політик |
| `X-RateLimit-Remaining` | Залишок доступних запитів | Якщо значення наближається до `0`, клієнту слід сповільнити надсилання запитів (client-side throttling) |
| `X-RateLimit-Reset` | Час скидання ліміту (Unix timestamp у мілісекундах) | Точний момент, коли квота `Remaining` повністю оновиться |
| `Retry-After` | Час очікування в секундах (при статусі `429`) | Обов’язкова пауза перед повторним надсиланням відхиленого запиту |

```json
{
  "code": 5016,
  "message": "Rate Limit Exceeded",
  "retry_after": 30,
  "details": {"limit": 20, "count": 21, "excess": 1, "reset_at": 1792083600000}
}
```

Auth-обмежувач не повертає details. У разі спам-блокування загальний middleware повертає code=5039, message=spam_blocked, blocked_until і remaining_seconds. Поріг звичайного вікна — 400 зайвих запитів, базове блокування — 5 хвилин; для AI поріг становить 200 зайвих запитів за секунду.

Обмежувач не робить запити зміни ідемпотентними. Після розриву мережі спочатку перевірте стан ресурсу. Для CDN явний конфлікт шляху повертає 409; це не відповідь 429 і не підтвердження успішного перезапису.

## Захист Cloudflare

Cloudflare також може відхиляти або блокувати запити незалежно від лімітів API, зокрема за великого потоку з однієї IP-адреси. Єдиного гарантованого порога у 10 000 запитів за секунду немає: поведінка залежить від правил захисту та характеристик трафіку. [Cloudflare](https://developers.cloudflare.com/waf/rate-limiting-rules/).
