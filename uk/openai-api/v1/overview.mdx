## Вступ

**ER:LC Russia AI API** підтримує описані в цьому розділі методи Chat Completions, отримання моделей і синтезу мовлення. Для чату використовуйте `chat.completions.create` в OpenAI SDK з `base_url` / `baseURL`, що дорівнює `https://api.erlcrussia.com/v1`. Розширення ER:LC Russia описано на сторінках методів; підтримка решти API OpenAI не передбачається.

## Аутентифікація

Для виконання запитів передавайте ваш токен доступу в заголовку `Authorization`:

```http
Authorization: Bearer YOUR_API_TOKEN
```

Також приймаються заголовки `erlcrussia-api-ai-key` і `erlcrussia-api-key`. Передавайте ключ лише в заголовку запиту.

## Помилки

Помилки надходять у форматі OpenAI, тому SDK показує справжнє повідомлення. У `code` — рядковий код OpenAI (`invalid_api_key`, `model_not_found`, `insufficient_quota`, `rate_limit_exceeded`) або `null`. Числовий код ER:LC Росія з таблиці [кодів помилок](/uk/documentation/error-codes) надходить у `erlc_code`.

```json
{
  "error": {
    "message": "You exceeded your current quota, please check your plan and billing details.",
    "type": "insufficient_quota",
    "param": null,
    "code": "insufficient_quota",
    "erlc_code": "5038"
  }
}
```

## Сумісність з OpenAI

* `/v1/chat/completions`, `/v1/models`, `/v1/audio/speech` і `/v1/audio/transcriptions` працюють через OpenAI SDK.
* `/v1/realtime` працює за протоколом OpenAI Realtime: текст і голос на вході, голос на виході, хід позначається вручну. Див. [голосовий режим](/uk/openai-api/v1/realtime).
* Поля `temperature`, `top_p`, `max_tokens`, `max_completion_tokens`, `stop`, `n` і `response_format` приймаються, але не застосовуються.
* `usage` є у звичайній відповіді. У потоці він надходить, лише якщо передати `stream_options: {"include_usage": true}`: окремим чанком з порожнім `choices` перед `data: [DONE]`. Додатково в `usage` є `cost_credits` — списані AI-кредити.
* Помилки використовують типи OpenAI: `invalid_request_error`, `requests`, `insufficient_quota`, `server_error`. Коли закінчуються AI-кредити, надходить 429 з типом `insufficient_quota`, як в OpenAI.
* Кожна відповідь має власний `id` виду `chatcmpl-…`, як в OpenAI. Ідентифікатор діалогу передається окремо в `session_id`.
* Запит без `messages` або з порожнім масивом отримує 400 з `param: "messages"` і кодом `missing_required_parameter` або `empty_array`.
* Кожна відповідь містить заголовки `x-request-id`, `openai-processing-ms`, `x-ratelimit-limit-requests`, `x-ratelimit-remaining-requests` і `x-ratelimit-reset-requests`.
* Якщо генерація обірвалася, у потоці надходить подія `{"error": {...}}` у форматі OpenAI, а за нею `data: [DONE]`.

## Доступні моделі

| Модель | Персонаж Опис | Режим Роздумів |
|---|---|---|---|
| **`niya-1`** | **Нія** | Основна модель для швидких відповідей, консультацій щодо правил та модерації | Опціонально (за замовчуванням вимкнено, включається через `thinking: true`) |
| **`emmy-1`** | **Еммі** | Просунута модель для глибокого аналізу логів, складних конфліктів та коду **Завжди включений** (налаштовується рівень роздумів через `effort`) |
| **`hubert-1`** | **Хуберт** | Кастомний персонаж спільноти, що відповідає характерному ігровому стилі | Вимкнено |

Для Хуберта фірмовий суржик вимкнено за замовчуванням: він відповідає мовою останнього повідомлення користувача. Передайте `"surzhyk": true` у тілі запиту до `/v1/chat/completions`, щоб увімкнути фірмовий стиль.

## Ролі повідомлень

У масиві `messages` підтримуються стандартні ролі діалогу:
* `system` - додаткова інструкція або контекст вашого проекту (наприклад, роль Discord-бота або завдання сервісу), що накладається поверх базових правил моделі;
* `user` - повідомлення від користувача;
* `assistant` - попередня відповідь моделі для збереження контексту розмови.

---

## Параметри роздуми

Управління ланцюжком міркувань залежить від обраної моделі:

* **Для Еммі (`emmy-1`):** режим без роздумів **не підтримується** — модель завжди аналізує завдання перед відповіддю. Глибина аналізу налаштовується параметром **`effort`** (`string`) або заголовком `X-Reasoning-Effort`:
* `low` - коротка перевірка фактів та правил;
* `medium` *(за замовчуванням)* - збалансований детальний аналіз;
* `high` - вичерпний покроковий розбір;
* `extra` / `max` - граничний рівень аналітики з перевіркою гіпотез.
* **Для Нії (`niya-1`):** за умовчанням роздуми вимкнені для максимальної швидкості. Включаються параметром `thinking: true` (або `variant: "on"` / заголовком `X-Reasoning: on`).
* **Для Хуберта (`hubert-1`):** ланцюжок роздумів не використовується.

## Потоковий режим

Під час передачі `"stream": true` сервер повертає потік подій `text/event-stream`. Кожна подія містить стандартну структуру `chat.completion.chunk`:

```json
data: {"id":"chatcmpl-9b2f6c1e4a7d4c0e9f1a2b3c","object":"chat.completion.chunk","created":1726838400,"model":"emmy-1","choices":[{"index":0,"delta":{"role":"assistant","reasoning":"Анализирую правила сервера...","reasoning_content":"Анализирую правила сервера..."},"finish_reason":null}]}

data: {"id":"chatcmpl-9b2f6c1e4a7d4c0e9f1a2b3c","object":"chat.completion.chunk","created":1726838400,"model":"emmy-1","choices":[{"index":0,"delta":{"content":"Приветствую!"},"finish_reason":null}]}

data: {"id":"chatcmpl-9b2f6c1e4a7d4c0e9f1a2b3c","object":"chat.completion.chunk","created":1726838400,"model":"emmy-1","choices":[{"index":0,"delta":{},"finish_reason":"stop"}]}

data: {"id":"chatcmpl-9b2f6c1e4a7d4c0e9f1a2b3c","object":"chat.completion.chunk","created":1726838400,"model":"emmy-1","choices":[],"usage":{"prompt_tokens":812,"completion_tokens":96,"total_tokens":908}}

data: [DONE]
```

prompt_tokens містить системний контекст сервісу та передану історію, а не лише повідомлення користувача. Навіть короткий запит може містити близько 7000 вхідних токенів і коштувати приблизно 1 кредит; це приклад спостереження, а не фіксована ціна чи мінімум. Фактична вартість залежить від моделі, кешу та відповіді: перевіряйте usage.cost_credits. web_search:true дозволяє пошук, але не гарантує виклик; кожен виконаний пошук оплачується окремо.

Повний секрет повертається лише під час створення або ротації. Списки AI-ключів, перейменування та видалення повертають маску. GET /keys розкриває лише ключ виклику; інші ключі, навіть власні, замасковані. teamId — ID прив’язаної команди або null.

Створення AI-ключа та обмін монет потребують сесії власника. Звичайний HTTP-ключ, навіть з повним доступом, не дозволяє ці операції. Довірені сервіси використовують адміністративні методи з майстер-ключем.
