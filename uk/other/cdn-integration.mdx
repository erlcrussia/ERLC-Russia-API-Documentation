## Виберіть спосіб інтеграції

| Сценарій Спосіб |
|---|---|
| Зображення, документи, відео | Завантажити через `POST /v3/cdn/assets`, використовуйте публічний URL |
| Next.js | `assetPrefix` та завантаження тільки `.next/static` до запуску релізу |
| Звичайний HTML/CSS Повні URL CDN у `src`, `href` та `url()` |
| Серверний імпорт `POST /v3/cdn/assets/external`; Публічне HTTP(S) джерело перевіряється від SSRF |
| Свій домен `POST /v3/cdn/custom-domains`, DNS/TLS, verify та маршрутизація Host у Go Edge |
| CI/CD | Новий префікс релізу; при необхідності purge тільки власний префікс |

Виклики керуючого API виконуються на сервері з `erlcrussia-api-key`. Публічна доставка файлів ключа не вимагає. Організація повинна мати CDN namespace, ключ повинен бути прив'язаний до неї, а його власник мати доступ CDN.

На загальному домені URL має вигляд `https://cdn.erlcrussia.com/YOUR_TEAM_SLUG/images/logo.png`; MinIO-ключ - `YOUR_TEAM_SLUG/images/logo.png`. На своєму домені URL - `https://files.example.com/images/logo.png`; MinIO-ключ - `files.example.com/images/logo.png`. Проста зміна hostname не робить файл іншого namespace доступним: завантажте його в потрібний domain.

## Папки та шляхи

`folderId` групує файли в інтерфейсі. `pathEnabled=true` додає slug папки лише при завантаженні без явного path. `false` залишає звичайну групу. Перейменування папки не змінює старі URL-адреси. Явний зайнятий URL повертає 409.

## Кеш і помилки

Go Edge читає MinIO та прогріває SSD. `X-Cache` описує Go Edge; `CF-Cache-Status` - Cloudflare. Успішний purge означає прийняття операції, тому перевіряйте доставку окремо. Використовуйте незмінні імена релізів, не замінюйте вміст старого хешованого чанка.

Список custom-domains повертає масив без success-обгортки. GET assets з path повертає asset, а звичайний список - assets, pagination та stats. Відсутній ключ: 401/5007, немає доступу: 403/5009, зайнятий шлях: 409/5135, ліміт: 429/5016.

Усі кастомні домени використовують спільний ingress cname.erlcrussia.com. Go Edge перевіряє Host у реєстрі CDN: зареєстрований CDN-домен обслуговується там; HTTP 421 для інших Host надсилає запит до Redirect. Окремий конфіг для кожного домену не потрібний. Якщо реєстр недоступний, запит завершується 502, а не відправляється в інший сервіс.

Див. [Next.js](/ua/tutorials/nextjs-cdn-integration), [кастомні домени](/ua/tutorials/cdn-custom-domains), [CI/CD та purge](/ua/tutorials/cdn-cache-purge-cicd).


Незареєстрований або непідтверджений Host повертає 421 і через загальний Nginx потрапляє до Redirect зі сторінкою неприв’язаного домену. Збій реєстру повертає 502; відсутній файл підтвердженого CDN-домену лишається помилкою CDN.
