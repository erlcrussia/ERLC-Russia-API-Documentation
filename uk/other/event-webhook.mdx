Щоб отримувати вебхуки з гри:

1. Ви можете налаштувати вебхуки двома способами:
   - В особистому кабінеті на сайті: перейдіть у розділ **Токени -> Вебхуки** (`/my/tokens?tab=webhooks`).
   - На нашому Discord-сервері: виконайте команду `/вебхук управління`.
2. Вкажіть URL вашого **кастомного** вебхука та виберіть сервери:
   - **Усі сервери** (за замовчуванням) — вебхук прийматиме події з усіх серверів проєкту.
   - **Вибіркові сервери** — вебхук прийматиме події тільки з обраних серверів.
3. Перш ніж зберігати URL, обов'язково натисніть кнопку «Перевірити» / «Тест».
   - Система надішле тестовий ping-запит з підписом. Якщо ваш ендпоінт поверне HTTP `200 OK`, вебхук перевірено і готово до роботи.
4. Після успішної перевірки активуйте отримання даних.

<Danger>
   **Ми НЕ підтримуємо прямі вебхуки Discord. Система працює виключно з кастомними вебхуками (вашими власними обробниками).**
</Danger>

Ваш ендпоінт зобов'язаний перевіряти Ed25519 підписи на кожному запиті. Гра збереже лише ті URL, які пройдуть перевірку.

---

### Заголовки та Маршрутизація Серверів

Кожен надісланий вебхук містить інформацію про сервер-джерело події:

#### HTTP Заголовки:
* `X-Signature-Ed25519` — hex-кодований Ed25519 підпис.
* `X-Signature-Timestamp` — Unix-штамп часу (в секундах).
* `X-Server-ID` — ідентифікатор ігрового сервера, на якому сталася подія.
* `X-Server-Name` — зрозуміла назва / псевдонім сервера (наприклад, `МВС` або `MRP 1`), якщо налаштовано адміністрацією.

#### Тіло Запиту (JSON):
* `server_id` (string) — рядковий ідентифікатор ігрового сервера.
* `server_name` (string) — псевдонім / назва сервера.
* Корисне навантаження події (повідомлення, команда, виклик тощо).

---

### Вимоги

#### Ваш ендпоінт повинен приймати

* `POST` запити з JSON тілом.
* Ці заголовки на кожному підписаному запиті:
  * `X-Signature-Ed25519` (hex-кодований Ed25519 підпис).
  * `X-Signature-Timestamp` (рядок Unix timestamp).
  * `X-Server-ID` (ідентифікатор сервера).
  * `X-Server-Name` (назва сервера).

#### Ваш Ендпоінт Повинен:

1. Прочитати **сирі байти тіла запиту** точно в тому вигляді, в якому вони отримані (не серіалізуйте JSON наново).
2. Прочитати `X-Signature-Timestamp`.
3. Прочитати `X-Signature-Ed25519`.
4. Перевірити підпис для:

   `message = timestamp + raw_body`

   Де `timestamp` — це значення заголовка у вигляді рядка, об'єднане напряму з сирими байтами тіла.
5. Повернути:
   * **2xx** тільки якщо підпис вірний.
   * **4xx** якщо заголовки відсутні, невірні або перевірка підпису не вдалася.

### Публічний Ключ

Використовуйте цей Ed25519 публічний ключ (base64, SubjectPublicKeyInfo / SPKI):

```
MCowBQYDK2VwAyEArbRTkyh3A035YUWWZdyF3vck4QN3I7uU8cp7YaxocFE=
```

### Деталі Реалізації

#### Вхідні Дані

* `timestamp`: точний рядок з `X-Signature-Timestamp`.
* `sigHex`: точний рядок з `X-Signature-Ed25519` (hex).
* `rawBody`: сирі байти тіла запиту.

#### Кроки

1. Декодуйте `sigHex` з hex у байти.
2. Побудуйте `message` як:
   * Байти `timestamp` в UTF-8
   * Одразу слідом `rawBody`
3. Перевірте Ed25519 підпис за допомогою публічного ключа вище.

#### Поширені Помилки

* Не використовуйте розпарсений JSON об'єкт для перевірки. Використовуйте тільки сирі байти тіла.
* Не додавайте роздільники чи пробіли між timestamp і тілом.
* Обробляйте підпис як hex, а не base64.
* Переконайтеся, що ваш фреймворк не поглинає тіло до того, як ви його захопите.

---

### Які події відправляються?

В даний час гра відправляє вебхуки для:

* Повідомлень, що починаються з **;**
  * Це дозволяє створювати власні внутрішньоігрові команди!
* Emergency Calls (Екстрені Виклики)

У майбутньому можуть бути додані нові події. Зверніть увагу: система вебхуків не призначена для заміни опитування HTTP API або WebSocket.
