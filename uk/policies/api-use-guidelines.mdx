Використання API ER:LC Росія пов'язане з низкою зобов'язань. Незалежно від того, створюєте ви Discord-бота, сайт бізнесу або будь-яку іншу інтеграцію, ви повинні суворо дотримуватися цих правил, щоб зберегти доступ до API та захистити нашу спільноту.

## Область підтримки

**Ми надаємо технічну підтримку щодо API виключно розробникам, які мають прямий доступ до свого коду**. Якщо ви створюєте продукт для кінцевих користувачів (наприклад, бот для інших серверів або свого бізнесу), ви несете відповідальність за їхню підтримку самостійно. Команда розробки ER:LC Росія не вирішуватиме проблеми користувачів, які просто використовують ваш сервіс.

## Заборонені дії

<Danger>
  Наступні дії **суворо заборонені** і призведуть до **безстрокового відкликання** доступу до API (блокування токенів), а також до можливих банів на наших ігрових серверах та в Discord:

  * **Нюкінг, рейди або краш** серверів та Discord-каналів вашим додатком.
  * **Абуз командами та багами** нашого API.
  * **Видавання себе за** інших гравців, адміністрацію або розробників проєкту.
  * **Поширення дезінформації**, неправдивих відомостей або злив конфіденційних даних.
  * **Погрози та шантаж** користувачів у будь-якій формі.
  * **Спам, флуд та DDoS-атаки** на ендпоінти API або пов'язані сервіси.
  * Будь-які інші деструктивні дії, вчинені зі шкідливими намірами.
  * **Недотримання [офіційних правил API ER:LC](https://apidocs.erlc.gg/policies/aups)** при інтеграції нашого API для ER:LC.
</Danger>

### Правила спільноти ER:LC Росія

API не може використовуватися для дій, що порушують Правила Спільноти ER:LC. Вони доступні [**за цим посиланням**](https://wiki.erlcrussia.com).

## Безпека даних та ключів доступу

Ви несете повну відповідальність за безпеку ваших API-ключів, токенів авторизації та будь-яких даних, які повертає API.

* Не публікуйте ключі у відкритих репозиторіях (GitHub, GitLab тощо).
* Не залишайте їх у клієнтському коді (фронтенді), де їх може скопіювати будь-який користувач.
* Якщо ваш ключ було скомпрометовано або стався витік, **негайно повідомте нас про це через тікет у Discord**. Ігнорування витоку або невчасне сповіщення адміністрації може призвести до **безстрокового блокування** вашого доступу до API.

## Оптимізація та навантаження

Якщо ваш сервіс обробляє великий обсяг запитів, ви зобов'язані реалізувати адекватні заходи **кешування даних**, **обмеження частоти запитів** та **коректної обробки помилок (наприклад, 429 Too Many Requests)**. 

Ми залишаємо за собою право тимчасово або назавжди обмежити доступ для будь-якого додатка, який перевантажує сервер, знижує продуктивність інфраструктури або створює загрозу стабільності проєкту.
