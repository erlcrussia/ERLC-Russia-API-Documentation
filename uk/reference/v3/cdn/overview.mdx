Архітектура CDN V3

## Як влаштовано зберігання

Кожен ассет зберігається у MinIO під ключом **`{domain}/{path}`**:

| Частина ключа Що таке |
|---|---|
| `domain` | Slug організації; `default` - тільки ER:LC Росія. чи підтверджений кастомний домен організації |
| `path` | Довільний шлях файлу, наприклад, `branding/logo.png` |

Єдиного префіксу категорії більше немає: якщо шлях заданий явно, він використовується як є. Якщо шлях не заданий, він генерується автоматично (з розширення файлу).

## Організація та доступ

Перед роботою прив'яжіть свій ключ до організації:

```bash
curl -X PUT https://api.erlcrussia.com/v3/cdn/team \
  -H 'erlcrussia-api-key: YOUR_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{"teamId":"YOUR_TEAM_ID"}'
```

Власник ключа має бути власником, адміністратором або учасником організації з дозволом CDN. Кожен запит повторно перевіряє членство. Без прив'язки ключа запит відхиляється. Необов'язковий `teamId` у query має збігатися з прив'язкою. Публічні CDN-маршрути не приймають майстер-ключ або внутрішній секрет замість ключа користувача; потрібна роздільна здатність V3.

На `cdn.erlcrussia.com` звичайна організація отримує лише `/{slug}/...`. Slug містить малі латинські літери, цифри, `_` і `-`. Корінь та `/erlcrussia/...` належать основній організації ER:LC Росія. Вона також не може записувати в зарезервовані шляхи інших організацій. На підтвердженому кастомному домені організації доступні довільні шляхи всередині її namespace.

Асети, папки, статистика та операції з ID обмежені організацією ключа. Папка інтерфейсу не замінює перевірку власника ресурсу.

## Потік завантаження

```
UI → POST /v3/cdn/assets?path=branding/logo.png
        заголовок: erlcrussia-api-key
API  → объект в MinIO:  {domain}/{path}
API  → запись в базу
API  → асинхронно POST {EDGE}/v3/warm
        заголовок: erlcrussia-api-edge-key
        тело: { domain, path, mimeType, size, sha256, isPinned }
EDGE → GET MinIO напрямую, кладёт файл на SSD
```

URL для скачування передавати не потрібно: edge сам збирає ключ із `domain` та `path`.

## Потік читання

```
Браузер → GET https://cdn.erlcrussia.com/{domain}/{path}
EDGE:
  HIT  → отдаёт файл с SSD (Range 206, ETag, 304)
  MISS → GET MinIO/{domain}/{path} → отдаёт клиенту и асинхронно кладёт на SSD
```

API V3 у цьому ланцюжку не бере участі. Origin-ендпоінтів API немає, доставка через API V3 не передбачена.

## Потік скидання кешу

```
UI → POST /v3/cdn/assets/purge?domain=default&prefix=branding/
API → POST {EDGE}/v3/purge?domain=default&prefix=branding/
        заголовок: erlcrussia-api-edge-key
EDGE → удаляет файлы с SSD и записи из SQLite
Следующий запрос → MISS → edge сам тянет свежий файл из MinIO
```

## Папки та публічні шляхи

| Дія | Вплив файлів |
|---|---|
| Створення папки | ні |
| Перейменування папки **ні**, файли залишаються на своїх шляхах |
| Видалення папки | **ні**, файли залишаються і втрачають прив'язку |
| `PATCH /cdn/assets` з `folderId` | лише угруповання в UI |
| `PATCH /cdn/assets` з `path` | фізичне перенесення об'єкта в MinIO |

## Авторизація

| Заголовок | Де приймається |
|---|---|
| `erlcrussia-api-key` | Усі маршрути `/v3/cdn/*` (також підтримується `X-API-Key` та `Authorization: Bearer <токен>`) |

Ключ передається виключно у заголовку. Query-параметри `?apiKey=` та `?token=` не підтримуються.

## Угоди про query-параметри

| Параметр | значення |
|---|---|
| `domain` | Простір імен. Типово slug організації ключа (`default` тільки для ER:LC Росія) |
| `ids` | Список ID через кому |
| `path` | Точний шлях усередині простору імен
| `prefix` | Префікс шляху для групи файлів
| `folderId` | Папка інтерфейсу: `root` без папки, `all` без фільтра |
| `page`, `limit` | Пагінація списку, `limit` максимум 100 |

`pathEnabled` керує префіксом лише нових завантажень без явного path. Папки не переміщують завантажені файли. Кастомні домени керуються через `/v3/cdn/custom-domains`; `/v3/cdn/domains` перераховує namespace з ассетами.
