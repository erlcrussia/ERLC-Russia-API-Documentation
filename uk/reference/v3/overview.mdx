Базова адреса API: `https://api.erlcrussia.com/v3`.

## Авторизація

Серверна інтеграція передає ключ користувача в `erlcrussia-api-key`. Управління CDN та редиректами вимагає прив'язки ключа до організації та дозволу власника ключа на відповідний сервіс. Секретні ключі не розміщуються у браузерному JavaScript. Маршрути профілю та підписок користувача використовують сесію erlc_auth, а вхідні PRC-вебхуки – підпис.

## Вибір маршруту

| Завдання Маршрут |
|---|---|
| Статус ігрового сервера `GET /erlc/server` |
| Discord/Roblox зв'язку | `GET /users`, `POST /users` |
| Файли та папки організації | `/cdn/assets`, `/cdn/folders` |
| Кастомні CDN-домени | `/cdn/custom-domains` |
| Редирективи організації | `/teams/{teamId}/redirects` |
| Ключі власника `GET /keys?api=true` |
| Статус сервісу `GET /health` |

## Формати відповідей

У Формат відповіді залежить від методу. GET users з одиночним discordId повертає `{ "robloxId": "123456789" }`; plural-параметри та POST повертають масив пар. Не знайдений одиночний зв'язок дає 404, порожній batch - 200 та []. ID передавайте рядками і зіставляйте batch за ID, а чи не за позицією.

GET cdn/assets повертає assets, pagination та stats. Точний path без ids/prefix повертає asset. GET cdn/custom-domains повертає масив без успіху. GET keys повертає масив для одного типу та об'єкт api/websocket для двох типів. Поле restrictions не є повною ефективною політикою доступу.

GET keys повертає секретні значення ключів власника, включаючи інші сервери. Використовуйте його лише у довіреному серверному середовищі та не логіруйте відповідь. Прив'язку ключа до організації не слід вважати обмеженням для решти ресурсів власника.

## Помилки та повторні запити

Основні поля помилки — `code` і `message`; додаткові поля залежать від причини. За HTTP 429 враховуйте `Retry-After` та заголовки лімітів. Значення можуть змінюватися; базові значення та правила повторних запитів наведено в [обмеженнях запитів](/uk/documentation/rate-limits).

Завантаження CDN повертає 200. Повтор зайнятого явного path повертає 409 і не перезаписує об'єкт. Для релізів використовуйте новий префікс; не повторюйте змінну операцію наосліп після мережевого обриву. Purge планується асинхронно: success не підтверджує завершення очищення всіх рівнів кешу.

GET health може повернути 200 з status=degraded при проблемі Redis або ігрового кешу; недоступна база дає 503. Перевіряйте одночасно HTTP-статус та JSON.

Див. [інтеграцію CDN](/uk/other/cdn-integration) та [Next.js і CDN](/uk/tutorials/nextjs-cdn-integration). Поля JSON, HTTP-заголовки та значення прикладів не перекладаються, щоб зберігати контракт.
