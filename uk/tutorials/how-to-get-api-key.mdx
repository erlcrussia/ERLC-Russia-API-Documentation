## Отримання доступу

<Steps>
  <Step title="Увійдіть на сайт">
    Увійдіть через Discord на [сторінку ключів](https://erlcrussia.com/my/tokens). Вона показує видані вашому акаунту права та ключі. Якщо доступу бракує, зверніться до адміністрації проєкту в Discord; команди перегляду не надають нових прав.
  </Step>
  <Step title="Дочекайтеся схвалення">
    Після схвалення права прив'язуються до вашого Discord-акаунта.
  </Step>
  <Step title="Відкрийте ключі на сайті">
    Ключі та вебхуки знаходяться на сторінці [erlcrussia.com/my/tokens](https://erlcrussia.com/my/tokens) після входу через Discord.
  </Step>
</Steps>

## Види ключів

| Ключ | Для чого | Де знайти |
|---|---|---|
| API-ключ | HTTP-запити до API V3 | `/my/tokens/api`, команда `/апи просмотр` |
| WebSocket-ключ | Підключення до [WebSocket](/uk/other/websocket-gateway). HTTP-ключ тут не підходить | `/my/tokens/websocket`, команда `/вебсокет просмотр` |
| AI-ключ (`sk-…`) | [AI API](/uk/openai-api/v1/overview) | `/my/tokens/studio` |

Вебхуки подій налаштовуються на сторінці `/my/tokens/webhooks`; переглянути їх можна також командою `/вебхук просмотр`. Докладніше — у розділі [Вебхук подій](/uk/other/event-webhook).

## Як передавати ключ

Передавайте API-ключ у заголовку `erlcrussia-api-key`:

```http
erlcrussia-api-key: YOUR_API_KEY
```

Заголовок `Authorization: Bearer YOUR_API_KEY` теж приймається. Ключ у query-параметрах не приймається.

<Danger>
  Не публікуйте ключі й не зберігайте їх у коді, що виконується в браузері. Якщо ключ витік, одразу перевипустіть його через [`POST /v3/keys`](/uk/reference/v3/keys/regenerate-keys) і повідомте адміністрацію проєкту.
</Danger>
